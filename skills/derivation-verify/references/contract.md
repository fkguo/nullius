# Derivation verification contract

Independent confirmation requires at least two evidence lanes independently constructed or derived and executed from a neutral question and raw inputs. Record method diversity, model-family diversity, execution independence and input independence separately. Same or similar methods, the same algorithm name, matching hashes or shared legitimate libraries do not by themselves disqualify a lane. Agent names, seeds, reworded prompts, copied answers and simple reruns of the original implementation do not establish independence. Different methods with contaminated input framing still fail. A fresh assessor must substantively inspect the actual steps, method preconditions, known defects and diagnostic power with exact source spans and reasons; a self-filled no-defect checkbox is insufficient. Missing, rejected, stale or non-diagnostic evidence does not count. Keep an explicit project-specific different-method risk requirement when that requirement tests a known shared failure mode.

Input independence also requires that a lane carry no operator memory: no user-level instruction files, no project instruction files of the operator's checkout and no auto memory of earlier sessions, because these routinely record the conclusion under test or the author's initial judgment; whatever a lane legitimately needs comes from its own request. The Claude CLI lanes exclude them by default and record the allowed sources per invocation (`context_sources.json`, carried in the lane's captured records).

Inputs: `context`, optional bounded `max_iter`, and `claims` with `id`, `statement`, `report_format`, optional `method0` and `method1` hints. A claim may set `requires_method_diversity: true` and describe `method_diversity_risk` for an explicit project-specific shared failure. Native lane records add `family`, `execution_id`, `method`, `canonical_answer`, complete `derivation`, optional `derivation_summary`, `confidence`, observed `transport` and optional strict `checkable_form`.

Every fresh blind lane receives the question, raw premises, canonical format and its own optional method hint; tie-break lanes receive no prior answers. Lane outputs give `canonical_answer`, the complete written `derivation` with every mathematical step stated (no length limit), `confidence`, optional navigation-only `derivation_summary` and `checkable_form`. The runtime records each exact request and raw returned output, successful invocation, source hashes and captured original tool records when available. Native Workflow lanes require actual calls observed within that executor. Python external native records have no validated capture authority and are unavailable for confirmation; supplied transport, success flags and hashes cannot count or exclude available CLI execution. Serialized receipts remain readable but cannot recreate runtime observation. CLI invocations use fresh directories and durable records; the default record directory is beside the requested matrix output, or beside the claims file for stdout. Absent original steps, nonzero/failed invocations and stale source/transport records refuse. In the CLI executor (`scripts/run_multi_backend.py`) a lane stopped by the provider's safeguards is recorded in `provider_refusals` as a refusal of that request, even when the CLI continued afterwards and exited 0; it contributes no derivation and no family, and a stopped comparator appears in the judge evidence with status `provider_refusal`. The stream signal needs live capture (the default for Claude); the Native executor records a stopped lane only as unavailable.

The fresh comparator receives the complete original derivations and runtime request/output/execution records. When every lane fits one request, a single comparator request holds every lane's complete material and supplies clustering, recomputation, every lane's assessment and any method risk together, as before (its only change is the one-contiguous-span sentence below). Otherwise each lane's assessment is made in its own comparator request that holds that lane's complete material, and only that lane; a joint request supplies `majority_indices` and equivalence/adjudication results over the canonical answers and holds no lane material, so any assessment it volunteers is discarded; an explicit method risk is assessed in one request per lane pair holding both complete materials. Entries a lane or pair request gives for any other index are discarded. Because the joint request sees canonical answers only, a lane assessment in this form counts only with `answer_support`: a literal `supports_canonical_answer: true`, an exact span of the concluding steps quoted under the construction rule, and a substantive reason. In this form no request reads two lanes' bodies except the pair requests of an explicit method risk, so text shared between lanes' bodies is not compared by one reader; `request_capacity.comparison_form` records `single_request` or `per_lane`. A judge's verdict is assembled from its own requests only, and panel aggregation is unchanged. Each lane assessment supplies `independence_assessments`. Every assessment has a source-grounded `observed_method`, `index`, `input_independent`, `execution_independent`, `construction_independent`, `method_applicable`, `diagnostic`, `unresolved_defects` and `evidence`. Evidence contains `input`, `execution`, `construction`, `applicability`, `diagnostic`; each item has an exact `source_span` and a substantive `reason`. Construction, applicability and diagnostic spans must occur in the text of that lane's `derivation_context` outside every answer-shaped JSON object, when `derivation_context` is present (the complete original output, given only when it holds assistant text outside the selected object; answer-shaped objects are the selected one and every other decodable JSON object with a `canonical_answer` or `derivation_summary` key, such as drafts, wrappers and near-copies), or in its complete structured `derivation` body as read (decoded from the JSON quoting it carries inside that output), with line endings compared as equal. The fields of answer-shaped objects, including `derivation_summary`, are never quotable derivation steps, and quotes never join text from the two sides of such an object; only input and execution may also quote the observed `transport` record (as the packet encodes it, or any of its decoded string values) or the `derivation_summary`. The comparator packet carries each lane's original text once as the structured `derivation` field and once as `transport.raw_output`, or as `derivation_context` with the transport marking `raw_output_given_as` when additional assistant text exists; no other packet field adds a copy, and the span check reads the same texts rather than a concatenated copy. Captured original records (`transport.captured_records`) are carried per record, and the packet states for each how and why: `by_reference` (path, SHA-256 and size from `artifact_refs`) only when packet assembly proves the bytes equal a shipped field or, for the terminal sidecar, the stream's terminal event re-serialized; a live stream as `content_blocks`, its content in emission order, where an assistant or streamed text block, or the terminal result text, whose complete value equals `transport.raw_output` (or `derivation_context`, or `derivation` when it is the context) is replaced by a reference to that field, proven equal to at assembly, and every other block and field (user and synthetic messages, tool use, tool results, thinking text, system, message and result fields such as tools, model, stop reasons, errors and permission denials, unrecognized lines) stays verbatim; any other record, or one whose reference does not identify the captured bytes, `inline` verbatim. Only ids, timestamps, usage, cost and timing counters, request-status, thinking-token and rate-limit events, stream start/stop markers, empty thinking blocks and thinking signatures are not shown; the complete file stays identified by its reference. Input and execution spans quote captured content only as the packet shows it: content carried by reference through the shipped field it equals, inline content through the inline record. With capture on, one complete lane of about 14 kB takes about a third of the default request window. Every source span is one contiguous exact copy of text as read; joined passages, ellipses and paraphrases are not quotes and refuse. Duplicate, missing, rejected, stale or unsupported assessments count as zero. Neither the author nor an unfilled checklist approves a lane.

Read coverage, not length, decides whether lane material counts. Length decides only carriage. Material that fits the conservative byte budget is inline. Above it, the complete material still travels inline and the request counts only when the comparator's own runtime-observed capture shows token usage within the configured window and no compaction; the byte budget is a conservative upper bound on tokens, observed usage is the measurement, and a runner that observes no usage leaves such material unavailable as content not completely read. Only material whose bytes exceed four times the token window, so that even at four bytes per token it would not fit, is read from frozen files: the lane's packet entry, encoded exactly as an inline request encodes it, is frozen before the comparator starts into read-only part files (each at most 24,000 bytes and 1,500 lines; lines cut after each JSON `\n` escape and at most every 2,000 characters, never inside an escape and never before U+FEFF, which Read strips at a file start, so a line may exceed 2,000 characters by a run of U+FEFF; joining all lines of all parts in order with nothing between them gives back the entry byte for byte) with SHA-256 and size, in a directory of that request's own holding only its lanes' parts, and the comparator reads them with read-only file tools (Read, Glob, Grep) with that directory as its working directory. From the comparator's own runtime-observed capture, a byte counts as read only when a Read result returned the line holding it, numbered as that line, with exactly the frozen text. The request's verdict counts only when every byte of every required file was returned, every returned line of a frozen file equals its frozen text, no tool outside the read-only set was used, no context edit was applied by the provider during the session, the verdict is given in the final message after the last read, and the files still hold their frozen bytes; otherwise it is unavailable as content not completely read, never truncated. A multi-turn reading session is bounded by each model call's own observed usage (the larger of its start and final counts, field by field; a call with no input count refuses), since the result event sums every call. Only a newline ends a captured event line. Only a comparator whose capture records each tool call and the content returned to it (Claude CLI live capture) can read material larger than one request; other comparators, injected host callables and the Native executor, whose host protocol returns one object per call with no capture of reads, leave such material unavailable as content not completely read. A judge that can be shown fewer than two lanes completely sends no request.

Both executors require at least two assessed independent agreeing lanes. Same/similar methods or one model family may satisfy that floor. Explicit method-risk requirements remain additional conditions, consumed through fresh `method_risk_assessments`: each names a pair of eligible indices, literal `addresses_shared_failure` and `methods_distinct` booleans for actual mechanisms, a concrete `risk`, substantive `method_analysis`, and exact source spans/reasons from both actual derivations, each span occurring under the same rule as construction spans. Different hint names or wording do not satisfy this condition. The assessor must explain whether actual method mechanisms independently test or avoid the declared shared failure; absent or unsupported assessments refuse. The whole complete lane packet is hash-bound to the current Python comparison; Native execution retains the exact compared packet. Changed original material invalidates the comparison. CAS establishes equivalence only among assessed forms. Both CAS and LLM comparison require adjudication agreement; an explicit veto cannot be overridden by equality of supplied forms. Method applicability and scientific truth remain distinct: reviewer acceptance does not certify truth.

Outputs retain complete `derivation_records` including runtime-observed request/output receipts, the matrix, `converged`, `independent_confirmations`, `cross_family_confirmations`, `verification`, family pool, iteration counts and native admission records. `independence_evidence` separately records examiner-observed method diversity, caller `method_hints`, model-family diversity, accepted evidence indices and input/execution assessment status. Missing reviewer capability is unavailable rather than an approval. Tests are offline acceptance witnesses, not independent scientific results.

Comparison booleans must be literal JSON booleans; strings and numeric substitutes never approve. Failed/nonzero/timeout launchers cannot reuse prior output.

The Native matrix retains every original claim in input order, including execution failures. `total_claims` is the original `claims` length; failed or missing host results produce `status=unavailable`, `converged=false`, zero confirmations, no invented answer and an explicit `failure_reason`. Their original ids remain in `unconverged`. A surviving successful subset cannot establish full convergence.

An accepted comparison must enumerate at least two eligible indices and report their exact cardinality. Its published answer must represent that adjudicated cluster. CAS equality cannot accept an empty, singleton or different cluster, override a veto, or publish another cluster's answer. Inconclusive and contradictory cardinalities leave zero accepted confirmations.

Claude stream capture preserves all assistant text messages and blocks in original order, reconciling snapshots and deltas by immutable message/block identity. Type conflicts and incomplete or inconsistent terminal records refuse completion. Runtime observations bind the exact complete report to its matching original successful terminal; capacity accounting uses only that terminal. Report bytes, including CRLF, stay unchanged. Additional original assistant text outside the selected JSON object enters the comparator as `derivation_context`; the structured `derivation` field remains unchanged. Earlier text must be assessed for necessary steps and contradictions, not discarded or automatically accepted.

Derivation comparator requests preserve every original lane and use `--context-bytes` and `--context-tokens` in the Python CLI, or `context_bytes` and `context_tokens` in Native args. The default token window is 200000 with separate protocol/output reserves. Python CLI comparisons require the current successful capture observation, exact request/report/cwd, and observed usage or a conservative bound; detected compaction refuses. Native and injected host protocols enforce conservative complete-input/output bounds and explicitly report provider token usage, authenticated CLI capture and compaction witnesses unavailable. A configured window is not provider capability introspection.

The current text comparator requires strict UTF-8 for required scientific bodies and transported source/input/output text. Preserving binary originals or their hashes does not provide evidence that their contents were assessed; an unsupported required original prevents confirmation.
