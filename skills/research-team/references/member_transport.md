# Member invocation evidence

A `full_access` member records its original request and final report invocations in `evidence.original_transport` (version 1). Both invocations must complete with exit code zero. Their canonical project-relative system, prompt and raw-output references include SHA-256 and byte size. Pre-invocation input hashes and the actual argument list bind the recorded files to execution. The original packet, runner source, complete proxy input and all invocation artifacts also appear in `outputs_produced`.

The `REQUESTS_ONLY` JSON supports `files_written: [{path, content, purpose}]`. `content` is the complete original UTF-8 source string; the proxy writes its exact bytes before reads and commands, only under `artifacts/runs/<tag>/research_team/<member>/independent/`. `--max-writes` bounds the complete write list without truncation. An identical existing file may be recorded with `created=false`; differing original bytes are never overwritten. Use literal command arguments to run the written program, without shell redirection or substitutions.

`original_transport.construction_refs` binds each audited source write to its original request index, raw model output, complete source snapshot, SHA-256 and byte size. Every own-prefix code source must match a whole original model-emitted string, including nested JSON strings or complete fenced source bodies. Complete source emitted through a generic I/O carrier receives the same byte-origin check; a pathname, author assertion, substring or examiner boolean cannot admit preseeded source. Libraries outside the member construction prefix remain legitimate assessment inputs rather than being rejected by shared path identity.

The source-assessor route currently requires strict UTF-8 for each required source, raw file input and captured command output. Binary or invalid UTF-8 material remains stored as original bytes, but cannot support a new confirmation through this text route; a hash does not establish that its contents were inspected.

Proxy reads preserve the full original bytes and SHA-256; `visible_chars` records the complete material supplied in the proxy response. A visibility or operation-count shortfall records pending request indices and refuses the episode, without truncating or silently dropping requested operations. Proxy command records bind the original request index, command, working directory, successful exit, full raw output and full-byte file inputs, including bounded literal/AST project-local source and data dependencies in supported languages and explicitly declared command `input_files`. Recognized unresolved dynamic loads, reads or evaluation are unavailable. This is not filesystem tracing, and opaque external-library reads cannot be assumed complete; external packages remain environment identity. Assessed member computation sources must belong to the frozen actual command-input closure. Missing, failed or changed original material prevents independent-reproduction admission before examiner assessments are considered. Historical evidence lacking this record remains readable but does not qualify for current admission.

The member proxy defaults to 20,000 characters per file read and 12,000 characters per command output. Configure `--max-file-chars` and `--max-cmd-output-chars` for larger complete material; exceeding either limit refuses the episode. These visibility limits are separate from source storage and assessor context capacity.

Select neutral reproduction input with the team-cycle `--reproduction-packet` option or `independent_reproduction.blind_packet` configuration. The selected route becomes the member writer’s ordinary `--packet` input. A route name does not prove blindness: the source assessor must examine the complete original packet, every actual read, command input and final-stage input for prior answers or author judgments.

The assessor receives complete original input and execution material separately from `derivation`, the complete scientific report and code body. Construction, applicability and diagnostic evidence must quote that body. Input and execution evidence can quote complete original transport. Request size is bounded without truncation by the configured context bytes and token window; observed usage and captured compaction evidence are retained when available. A transport fixture validates this protocol and does not establish scientific independence.

Positive gate admission requires a new successful source-assessor invocation observed by the gate itself. Supply `--assessor-model MODEL` to the standalone reproduction gate or the convergence consumer, with optional `--assessor-runner`, `--assessor-timeout-secs`, `--assessor-context-bytes` and `--assessor-context-tokens`. The convergence consumer invokes the reproduction gate once after report consistency and original-report binding pass; the nested gate observes the fresh assessor process. Each call writes a distinct `assessments/<id>/assessment.json` and preserves its originals. Imported assessment JSON, hashes and exit flags cannot reconstruct current execution authority. `--assessment` explicitly rechecks a historical record without granting it current confirmation authority; unrelated historical records do not block a fresh call.

The `independent_reproduction.requires_method_diversity` and `method_diversity_risk` settings declare an additional project requirement. A fresh pair assessment must explain with both scientific bodies how distinct mechanisms address the named shared failure; method labels and agreement alone cannot satisfy it.

Capacity evidence requires an adjacent runtime observation of the actual successful invocation, including requests that fit the conservative byte bound. The local runtime binds the complete original request, actual report locator, working directory and captured bytes using its host authority; recalculating project artifact hashes cannot create that observation. Verification trusts the runtime and owning OS account, and does not authenticate provider truth or scientific correctness. Historical unsigned records remain readable, but cannot supply new capacity acceptance; they are never retrospectively signed.

Current member admission requires a runtime-observed producer episode covering both successful model stages, the actual proxy operations, complete original material and published report copies. The local host authority binds their bytes and the complete evidence record; project-only edits and recalculated hashes cannot replace the observed episode. The final consumer accepts only producer-observed report paths whose full bytes match the original model report. Historical unsigned episodes remain readable and cannot supply new confirmations.

Every observed member file has a byte-identical durable original snapshot in the sealed episode, including temporary workspace inputs, actual runner material and captured model events. Normal workspace cleanup does not remove these originals. New admission checks their complete signed mapping; an old observation lacking durable originals remains readable but unavailable for new confirmation. Copied capture receipts cannot authenticate an invocation at a foreign report path.

Member origin trusts the configured runner and owning host runtime: the complete runner bytes are recorded, but no runner allowlist or provider attestation is claimed. Offline or injected host execution establishes a local process/callable observation; actual provider capacity evidence requires the corresponding CLI capture. The canonical team cycle performs one fresh source assessment at the final consumer, using the configured assessor request/execution budgets. Postflight retains deterministic evidence, clean-room and isolation checks. Consultation before convergence is advisory and grants no independent confirmation. An early stop or failed report check records no confirmation and does not spend an assessor call. A later eligible acceptance attempt, including a standalone gate invocation, always requires a new observation.

When the final consumer invokes the reproduction gate, it preserves the complete diagnostic verdict at `artifacts/runs/<tag>/research_team/independent_reproduction_gate.json` and forwards its failure reasons. This file is diagnostic output, available at final acceptance rather than postflight. The consumer reads the current subprocess stdout and exit status, never this file, to decide admission. The durable convergence receipt carries only the current accepted `confirmation_refs`; older diagnostic files are not current authority.

The owning account can read the authority key, including code executed by a member under that account; this authenticates against non-executing artifact tampering, not hostile same-account code. No OS sandbox or provider attestation is supplied.

The configured token window is frozen before the original reviewer subprocess starts and bound into its authenticated runtime observation. Changing historical window metadata cannot admit that receipt. Older observations without this policy remain readable and require a fresh execution for capacity acceptance.

Shared project dependencies appear as explicit assessor locators and source roles. Construction evidence must quote complete producer-origin member source, rather than a shared computation or self-reported prose. Each shared locator requires a substantive disposition quoting both member constructions; missing or conflicting dispositions cannot confirm independence. Invalid, ambiguous or missing explicitly selected configuration is unavailable at settings, assessor and final-consumer entry points, without default approval.
